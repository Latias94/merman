# Renderer benchmark report · 2026-11-23

## Overview

- **Node coverage.** Merman and its peers returned repeatable SVG on 139/145 with Pele, 139/145 with Mermaid v13. The plan contains 99 distinct sources.
- **Warm Node rendering.** 24 scenario/peer comparisons in the 12-scenario plan (8 consistent with verified drawing properties, 5 consistent on timing alone, 9 with mixed or tied rounds, 2 withheld for expected rejections).
- **CLI exports.** SVG (27 distinct sources planned, 3 batches per product and scenario), PNG (2 distinct sources planned, 3 batches per product and scenario).
- **Browser rendering.** Both modes completed on 2/2 selected family examples, with 6 blocks planned per mode.
- **Local Rust layout.** 28/32 observed Flowchart stress controls produced SVG under the default limits.

This Windows x64 run used released Merman 0.11.0 artifacts for Node, CLI and Web. With one fresh process per file, the Flowchart took 77.77 ms in Merman and 2,347.97 ms in mmdc for SVG (30.19× mmdc/Merman). For default PNG the medians were 99.97 and 2,457.30 ms (24.58×). Each median covers three sequential batches per product.

In a running Node process, the mixed Flowchart and Sequence batch made eight calls on two sources. Merman took 3.627 ms per batch, Pele 1.203 ms and Mermaid v13 2.150 ms. The median within-round peer/Merman ratios were 0.332 and 0.637. Both peers took less time in all eight rounds and passed the drawing properties declared for every request. For the tiny Flowchart, median import through first SVG was 40.79, 44.10 and 280.75 ms, respectively. The same workers' median peak RSS through the warm batches was 64.98, 60.04 and 67.95 MiB. Startup and memory figures are descriptive medians across eight workers per product.

In Chromium, the Sequence example took 171.55 ms in Merman Web and 279.25 ms in Mermaid.js 12.3.0 from a cold start to a publishable SVG (1.63× Mermaid.js/Merman). Warm delivery took 16.95 and 16.00 ms (0.94×). The shorter warm interval through SVG return and the byte check took 5.45 and 9.90 ms. Each median covers six blocks on this browser.

A separate readability check covered six SVGs from the four-node chain and the CI/Deploy diagram across three engines. All 30 expected labels contributed visible pixels. All 36 node pairs and 36 unrelated edge–node pairs had positive clearance at 1152 × 512 CSS pixels. The archive includes the previews, thresholds, clipping control and measured gaps.

## Reproduce this report

The portable receipt records the measured builds, workload fingerprints and observations. For each eligible Node timing pair it includes both workers' batch medians and their within-round ratio. [Portable measurement receipt](2026-11-23-windows-x64.json). [Download the raw audit data](<https://raw.githubusercontent.com/Latias94/merman/d17b7feaf461775b4a27db6edf4b08b21fef12b3/windows-x64-20261123.zip>).

To regenerate the Markdown beside the receipt, run this command from the repository root with the downloaded JSON path. For the original wording of an archived report, use the generator and template from its publication revision.

```console
python tools/bench/perf_runner.py workloads report --from path/to/measurements.json
```

Add `--check` to verify an existing Markdown file. To collect a new run, match the product versions, inputs, settings and sample counts for the operation you want to compare.
