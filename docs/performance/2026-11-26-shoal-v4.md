# Shoal aesthetic core benchmark · 2026-11-26

The refactor brought 500-node fan-in and fan-out to 3.841 ms and 3.839 ms for native SVG. Both exceeded the 2.5 ms target. Architecture's services example fell from 0.083 ms to 0.068 ms. The stripped WebAssembly feature slice grew by 2.28%. [Design decision](../adr/0103-shoal-aesthetic-core.md) · [Samples and digests](2026-11-26-shoal-v4.json)

## Native rendering and Node reference

The baseline was `24e2572e4` and the candidate was `48a3961cf`, both built in release mode with Rust 1.100.0 on an Apple M4 Pro running macOS 27.2.1. Native values are medians of 12 fresh processes per revision, with two untimed renders in each process. The rounds alternated baseline, candidate, candidate, baseline, with an additional baseline control before the candidate. The collector verified the backend and the returned SVG digest for every timed sample. Pele 1.13.0 ran under Node 26.11.0 with 12 warm calls in a separate worker per diagram. In a separate stage run, SVG emission accounted for about 1.9 ms on each 500-node fan. Parse took about 0.71 ms and Shoal's solve took about 0.25 ms. Sampling the native renderer found repeated SVG path-length calculations for Neo markers inside emission. The changes recovered a large intermediate fan-in regression by reserving enough room between a wide curve's first bend and the node row to prove stroke clearance. ## Geometry and artifact size

The final SVG witnesses measured a worst label balance ratio of 1.39 for the decision and release examples across four directions. The labeled bypass measured 1.29 with aligned first turns. The largest S-curve handle fraction was 0.46. Both 250-node fans painted 248 cubics over 249 edges, and both 500-node fans painted 498 over 499. The test also checked the decision's shared-face turn placement and tangent symmetry where curves were used. The compound replay drew all 339 cases, and 31 stress topologies drew successfully. The remaining topology reached the expected `maxEdges` limit. ## Reproduce

Freeze both plans once. Run the clock command on the baseline and candidate with the same `--plan` path and a release runner built at the specified revision. Repeat in the opposite order. Use the stage and Node procedures in the runbook for their separate measurements. [Runbook](RUNBOOK.md#compare-native-flowchart-layouts)

```console
python3 tools/bench/bench.py plan --suite full --scenario small-svg --scenario flowchart-nested-layout --scenario chain-500 --scenario scc-75 --scenario scc-100 --scenario scc-100-edges-reverse --scenario fan-in-500 --scenario fan-out-500 --out target/bench/shoal-v4-flowcharts.json
python3 tools/bench/bench.py plan --suite families --scenario family-architecture --scenario family-c4 --scenario family-swimlane --out target/bench/shoal-v4-families.json
python3 tools/bench/bench.py rust --plan target/bench/shoal-v4-flowcharts.json --metric clock --operation svg --site-layout shoal --resource-profile interactive --warmups 2 --samples 6 --verify-measured-svg --require-complete --out target/bench/shoal-v4-clock.json
```

Build the WebAssembly slice with the same toolchain and path remapping on both revisions. Record the stripped binary before measuring its gzip size.

```console
RUSTFLAGS="--remap-path-prefix=$PWD=/merman" cargo build --locked --profile wasm-size --target wasm32-unknown-unknown -p merman-wasm --no-default-features --features diagram-flowchart,diagram-agentflow,diagram-architecture,diagram-c4,diagram-swimlane,layout-shoal
wasm-tools strip -a target/wasm32-unknown-unknown/wasm-size/merman_wasm.wasm -o target/bench/shoal-v4-stripped.wasm
wasm-tools validate target/bench/shoal-v4-stripped.wasm
```
