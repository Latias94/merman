## Reproduce

Freeze both plans once. Run the clock command on the baseline and candidate with the same `--plan` path and a release runner built at the specified revision. Repeat in the opposite order. Use the stage and Node procedures in the runbook for their separate measurements. [Runbook](RUNBOOK.md#compare-native-flowchart-layouts)

```console
python3 tools/bench/bench.py plan --suite full --scenario small-svg --scenario flowchart-nested-layout --scenario chain-500 --scenario scc-75 --scenario scc-100 --scenario scc-100-edges-reverse --scenario fan-in-500 --scenario fan-out-500 --out target/bench/shoal-v4-flowcharts.json
python3 tools/bench/bench.py plan --suite families --scenario family-architecture --scenario family-c4 --scenario family-swimlane --out target/bench/shoal-v4-families.json
python3 tools/bench/bench.py rust --plan target/bench/shoal-v4-flowcharts.json --metric clock --operation svg --site-layout shoal --resource-profile interactive --warmups 2 --samples 6 --verify-measured-svg --require-complete --out target/bench/shoal-v4-clock.json
```

Build the WebAssembly slice with the same toolchain and path remapping on both revisions. Record the stripped binary before measuring its gzip size.

```console
RUSTFLAGS="--remap-path-prefix=$PWD=/merman" cargo build --locked --profile wasm-size --target wasm32-unknown-unknown -p merman-wasm --no-default-features --features diagram-flowchart,diagram-agentflow,diagram-architecture,diagram-c4,diagram-swimlane,layout-shoal
wasm-tools strip -a target/wasm32-unknown-unknown/wasm-size/merman_wasm.wasm -o target/bench/shoal-v4-stripped.wasm
wasm-tools validate target/bench/shoal-v4-stripped.wasm
```
