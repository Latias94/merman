# Maintenance text terminal comparison

Open `index.html` for the self-contained comparison. `comparison.png` is its full-page
capture in Microsoft Edge 156 at a 1160 CSS-pixel viewport and device scale 1.
The exact Mermaid inputs are byte-for-byte copies of the main comparison inputs:
Arial in both font settings, `theme: default`, `look: classic`, Kanban title `1`,
task `API` with `assigned: 'Li<br/>Jill'`, and class `API` with note `A&nbsp;B`.

- Kanban: the baseline SVG displays literal `<br/>` in the assigned names. The maintenance
  WASM emits an XHTML break, so both measurement and the visible label use two lines.
- Class note: the retained maintenance CLI actually exits with status 1 during
  `validate-well-formed-svg`, reporting `invalid XML entity reference: unknown entity &nbsp;`.
  Its original stderr bytes are retained in `class-note-before.txt` and displayed in the
  before panel. The CLI does not emit a before SVG; no substitute diagram is shown.
  The after SVG loads successfully and contains the intended nonbreaking space.

## Provenance

The maintenance baseline is `917d75836d8ed7ca77744d51270dec2f05e48ec2`.
Before results were generated by `/tmp/merman-deep-audit-20261028/09-cli` (`merman-cli 0.9.2`),
using parity SVG output and deterministic measurement. Its audit checkout has HEAD
`613e6a0b601c28b30fcb642c10b2ae552cb7b67d`; the six relevant class, Kanban, shared-text and
sanitizer source files were compared with the maintenance baseline and match byte-for-byte.
The binary SHA-256, exact commands, exit codes and source-file hashes are in `comparison.json`.

After SVGs were captured through `renderSvg` from this maintenance worktree's own
`platforms/web/dist/` runtime and `platforms/web/pkg/full/` package. No host text-measurement
callback was installed, so the WASM uses deterministic fallback measurement.
`comparison.json` records the hashes of the actual JS and WASM bytes served to the browser.
Inputs are shared with main; rendered results and the error capture were generated independently.

`wasm-inputs.json` is an unchanged copy of the full WASM build manifest.
All six package artifact hashes and both manifest digests were verified.
Of its 995 source inputs, 994 match the current maintenance worktree. The only difference
is one additional `(22, "length")` test expectation inside `#[cfg(test)]` in
`crates/merman-bindings-core/src/text_measurement.rs`. Removing only that line in memory
reproduces the manifest's exact input SHA-256. This is test-only drift; the build manifest
is retained as generated, and the comparison does not claim an exact current-tree input match.
